# 教师端安全待办说明

> 文档性质：**待办说明**（不是设计方案）。  
> 更新时间：2026-08-07  
> 语境：当前教师端为**本地演示开箱可用**而设计，不是生产级身份体系偷懒未做。

---

## 1. 现状：身份完全来自客户端自称

`4-stu-learning/server/runtime/routes.js:3`：

```js
const actor = (request) => request.headers['x-teacher-id'] || 'teacher-demo';
```

- 服务端**不验证**请求头里的教师身份；默认值 `teacher-demo` 本身就可用于读写演示场次。
- 所有教师 API 的 `actorId` / 授权比对都建立在这个未校验字符串上。

前端硬编码同一常量：`4-tea-leading/app.js:4`

```js
const TEACHER_ID = 'teacher-demo';
```

每次 `fetch` 通过 `x-teacher-id` 请求头送出（`4-tea-leading/app.js:272`）。

---

## 2. 授权边界过窄：只比对场次归属

`4-stu-learning/server/runtime/course-run-service.js:187-191` 的 `assertTeacherAccess(runId, teacherId)`：

```js
if (run.teacherId !== teacherId) throw httpError(403, '你无权访问该班级场次。');
```

含义：

- 只要请求头带上 `x-teacher-id: teacher-demo`，且目标 `run.teacherId === 'teacher-demo'`，即可通过全部教师接口。
- **没有**班级／学校／角色／会话令牌层级的授权。
- 知道 `runId` 且能伪造教师 ID 的调用方，理论上可读写该场次全部数据。

---

## 3. 影响面：现有接口能做什么

以下接口均走 `authorize` → `assertTeacherAccess`（`routes.js:29`），**演示环境下等价于“知道 runId 即可操作”**。

| 接口 | 代码位置 | 能做什么 | 生产不可接受的后果 |
|---|---|---|---|
| `GET /api/teacher/runs/:runId/snapshot` | `routes.js:48` | 读取全班姓名、实时位置、进度、设备状态、对话摘要 | 未授权人员可监控未成年人实时位置与学习状态 |
| `GET /api/teacher/runs/:runId/events` | `routes.js:50` | 读取场次事件流（含指令回执） | 可跟踪教师指令与学生响应时序 |
| `GET /api/teacher/runs/:runId/review` | `routes.js:51` | 课后回看：小组进度、干预时间线、审计摘要 | 可批量导出班级学习过程数据 |
| `POST /api/teacher/runs/:runId/commands` | `routes.js:89-94` | 发暂停、紧急集合、结束场次、人工通过证据等 18 种指令 | 可远程中断或篡改现场教学进程 |
| `POST /api/teacher/runs/:runId/roster/import` | `routes.js:64-67` | CSV 覆盖学生姓名与分组 | 可篡改班级名单与分组关系 |
| `PATCH /api/teacher/runs/:runId/participants/:id` | `routes.js:70-76` | 改学生姓名、小组、角色、触发设备重检 | 可错配角色或掩盖设备问题 |
| `PATCH /api/teacher/runs/:runId/alerts/:id` | `routes.js:79-86` | 改 P0/P1 告警状态 | 可掩盖安全类事件处理记录 |
| `POST /api/teacher/runs/:runId/audit` | `routes.js:53-61` | 写审计（含 `transcript.view_requested`、`privacy.override`） | 审计操作者不可信，合规证据链无效 |
| `POST /api/teacher/runs` | `routes.js:36-45` | 创建新场次，教师 ID 取自请求头 | 可冒名创建场次 |
| `GET /api/teacher/runs` | `routes.js:34` | 列出请求头对应教师 ID 的全部场次 | 可枚举该 ID 下所有班级 |

WebSocket 实况（若启用）：`GET /api/teacher/runs/:runId/live`（`routes.js:98-104`），同样只验 `assertTeacherAccess`。

## 4. 隐私边界：设计正确，但依赖尚未存在的身份系统

`4-tea-leading/README.md` 写明：教师默认只看 **AI 对话摘要** 与 **学习证据**，原文需生产身份与授权确认后才开放。

实现与之一致：

- 学生抽屉只渲染 `participant.learning.dialogueSummary`（`4-tea-leading/app.js:509`）。
- 「按授权查看原文」按钮（`data-action="request-transcript"`）**不返回原文**，只 POST 审计：`4-tea-leading/app.js:704-706`

```js
await request(`/teacher/runs/${state.runId}/audit`, {
  method: 'POST',
  body: JSON.stringify({ action: 'transcript.view_requested', ... }),
});
showToast('已记录原文查看请求；演示环境仅提供对话摘要。');
```

这条隐私设计**依赖**未来真实的身份与授权系统；在演示模式下，任何能调用 audit 接口的人都能留下“已请求原文”的记录，但还看不到原文。

## 5. 演示环境可接受 vs 生产不可接受

| 维度 | 演示环境（当前） | 生产环境 |
|---|---|---|
| 身份来源 | 硬编码 `teacher-demo` + 可伪造请求头 | 必须经 IdP／账号体系验证 |
| 授权粒度 | 仅 `run.teacherId` 字符串相等 | 班级／场次／角色／操作类型多维授权 |
| 审计可信度 | 操作者 ID 来自客户端 | 操作者必须与已认证会话绑定 |
| 数据暴露 | 本地单教师、单机器可接受 | 未成年人位置与对话摘要属敏感个人信息 |
| 指令风险 | 教师本人操作自己的演示班 | 需防冒发紧急集合、结束场次等高危指令 |

## 6. 上线前必须补的项（待办，非设计）

以下只列**必须做什么**和**不做的后果**；具体用 JWT、session cookie 还是哪家 IdP **尚未定案**，不在本文展开。

| 待办 | 不做的后果 |
|---|---|
| **真实身份认证**（替换可伪造的 `x-teacher-id`） | 任何人可冒充教师操作任意演示场次 |
| **服务端会话令牌**（短期、可吊销、与浏览器绑定） | 无法撤销泄露凭证；无法区分真实教师与脚本 |
| **按班级／场次的授权边界**（不止比对 `run.teacherId`） | 同一学校不同班级教师可能互访数据 |
| **审计操作者可信化**（审计写入必须来自已验证身份） | 合规调查时无法证明“谁发了紧急集合／谁看了摘要” |
| **高危指令二次确认与速率限制**（pause、emergency_rally、end_run 等） | 误触或恶意脚本可瞬间影响全班 |
| **生产环境禁用默认 `teacher-demo` 回退** | 未配身份时仍自动获得完整权限 |

## 7. 本文刻意不做的事

- 不修改 `routes.js` 或任何运行时代码（本轮 TC3 范围）。
- 不选定 JWT / Session / OAuth 等具体方案。
- 不把演示配置当成“临时欠账可以上线后再说”——**生产部署前上述待办为阻塞项**。
