# AI 对话系统 P0–P2 实施任务书

> 日期：2026-08-11
> 总负责人：Codex（主工作树）
> 并行执行：Cursor、Kimi
> 目标：完成平台规则、课程配置、运行时状态机、学生端呈现、评测与留痕的系统整改。每个阶段必须通过测试和证据审查后才能进入下一阶段。

## 1. 结果定义

完成时必须同时满足：

1. 学生可见的模型回复、固定话术、脚手架、验收反馈和工具提示都经过同一套安全、完整性、学段与答案保护边界。
2. 原子任务与证据汇总任务拥有不同的收口方式，不再统一要求二次提交。
3. 阶段卡、絮絮气泡、工具卡和验收反馈各司其职；一个回合只有一个主要行动。
4. 多 Step 任务的脚手架与当前 Step 对齐，升档状态不跨 Step 污染。
5. 安全提醒按真实事件触发；普通工具操作只显示一次简短安全提示。
6. 五门课程中未知配置、受保护答案泄露、不安全行动和无效阶段字段可被 lint 发现。
7. 真实模型评测覆盖入场、选角色、视频、照片、失败重拍、任务完成和转场，保存可复核的完整事件与版本指纹。

---

## 2. 不可破坏的全局边界

1. 学习状态仍由确定性状态机推进，模型不能自行完成 Step、任务或工具。
2. 紧急安全始终最高优先级；减少絮叨不能削弱真实危险场景的求助和教师通知。
3. 任务默认采用 `auto_on_last_step`：每个 Step 已独立完成合法验收后，最后一步通过即完成任务。
4. 只有文字明确要求跨 Step 整包复核、删改并统一提交时才显式配置 `explicit_bundle_submit`；明确要求任务级教师终审时配置 `teacher_confirm`。
5. 不用单纯扩大 token 或更换模型掩盖状态机、配置和 UI 问题。
6. 不读取、复制、提交或输出 `.env.local` 和任何密钥。
7. 三个执行者不直接覆盖彼此工作；并行分支由 Codex 审查后逐项合入主工作树。

## 4. Cursor：P0 静态契约与语义 lint

### 4.1 目标

把“文档中写了但运行时不识别”“L4 直接泄露保护答案”“Phase 提示过长”“明显不安全行动”等问题变成可定位、可测试的课程质量问题。

### 4.2 任务

1. 新建纯函数静态审计模块，例如 `server/course/course-quality-audit.js`，输入课程源文件和编译结果，输出稳定 issue：
   - `unknown_course_section`：`course.md` 未被编译器识别的二级标题；
   - `protected_scaffold_leak`：当前任务/Step 的 L1–L4 或学生可见引导包含其引用限制中的受保护词或精确保护值；
   - `unsafe_student_action`：高置信危险行动，如触摸展品、往地面倒水、向河中投放物体、靠近水边操作手机；第一阶段先报 warning；
   - `phase_prompt_over_budget`：Phase 提示超过当前运行时语义预算；
   - `stale_phase_capability`：提示词声明扫码分角色、自动聚合等当前配置或平台能力不存在的行为；
   - `timing_conflict`：Phase 叙述中的无操作提醒与任务结构化字段冲突。
2. 将审计模块接入 `scripts/lint-lesson.mjs`，issue 必须包含课程、文件、行号、code、level 和可执行修复说明。
3. 风险分级：
   - 直接保护答案泄露：error；
   - 未知规则标题：warning，等五门课程迁移完成后由 Codex 提升为 error；
   - 危险行动、超长提示、能力残留、时间冲突：warning。
4. 新建测试，不依赖真实模型：
   - 合成课程分别触发每个 code；
   - 安全文本不误报；
   - 格物真课程能发现 `螭首就是排水口`、`1142`、扫码残留和至少一项危险行动；
   - 现有结构 lint 行为保持不变。
5. 运行相关测试和全量课程 lint，提交分支 commit；交付 issue 数量与文件清单。

### 4.3 完成标准

- 新规则有单元测试和真课程回归。
- 不修改任何运行时回复行为。
- 不自动改课程内容。
- 分支有一个聚焦提交，提交信息说明新增了哪些 lint code。

## 5. Kimi：P2 评测、留痕与发布门禁

### 5.1 目标

把旧“92/92 机械通过”改造成可复核、会失败、覆盖真实旅程的质量评测基础设施。

### 5.2 任务

1. 修复 `run-ai-dialogue-eval.mjs`：
   - 按 `partIndex` 拼接全部 `assistant.completed`，不能只取最后一泡；
   - 保存原始 SSE 事件、bootstrap 回合、状态前后、工具调用和错误；
   - scenario 抛错、空样本、缺终态必须计为失败；
   - 阈值未达时设置非零退出码；
   - 每次结果保存到仓库内稳定的评测运行目录，临时文件只能作为中间产物。
2. 为每次运行记录可复现信息：runId、时间、模型/provider、主要参数、Git commit、课程 `contentVersion`、平台规则版本、语料版本、评测器版本。
3. 将指标拆成：
   - 硬契约：安全、泄题、状态、工具、完整终态；
   - 表达质量：语境相关、直接性、重复、模板兜底、无关安全提醒、完整句、年龄适配；
   - 体验事件：阶段卡、提示、工具卡顺序和相对时间。
4. 新增确定性质量检查：
   - 代码性截断或未完成句；
   - `这句话我刚才说过了`、`没完全接住`等错误兜底；
   - 非安全样本出现紧急安全模板；
   - 学生明确要求不给答案时出现受保护答案；
   - 多气泡合并后不得丢字。
5. 扩展语料结构，使后续可以描述 `user_text`、`tool_result`、`lifecycle_event` 和浏览器事件；至少新增以下关键旅程 fixture：
   - 视频自动完成；
   - 选角色前后同会话；
   - 照片不足 → 删除/重拍 → 通过；
   - 最后 Step 自动收口与证据汇总任务显式提交；
   - 普通拍照无过度安全提醒；
   - 真实危险场景教师求助。
6. 在 `package.json` 增加清晰命名的评测脚本；普通 `npm test` 不直接调用付费模型，CI/live eval 分开。
7. 新建测试覆盖汇总、阈值、失败退出、完整事件保存和隐私清理。

### 5.3 完成标准

- runner 可以对合成结果稳定判定通过/失败。
- 输出文件完整、可重建、无密钥和学生隐私。
- 付费 live eval 不会被普通单测意外触发。
- 分支有一个聚焦提交和迁移说明。

## 6. Codex：P0、P1、P2 跨层实现与集成

### P0：权威和统一输出边界

1. 在 SPEC 明确唯一规则层级及各文件的生效字段。
2. Phase 提示由无语义截断改为结构化字段；迁移前保持兼容并报警。
3. 建立统一 `StudentFacingPolicy`，覆盖模型、fastWorkflow、fastGuidance、voice、验收反馈和工具提示。
4. 完整性、答案保护、学段和来源策略在所有输出路径一致。
5. 建立逐回合 trace，记录决策来源、输出路径、Prompt/规则/contentVersion 指纹和状态变化。

### P1：任务生命周期和回合编排

1. 新增任务收口模式：`auto_on_last_step`、`explicit_bundle_submit`、`teacher_confirm`。
2. 课程任务默认自动收口；明确需要跨 Step 整包复核的任务才显式配置 `explicit_bundle_submit`，明确需要任务级教师终审的任务配置 `teacher_confirm`。
3. 建立 `TurnPlan`：唯一主要回应、下一动作、工具、快捷回复、安全动作、状态变化、来源和呈现节奏。
4. 消除阶段卡、气泡、工具卡和验收反馈之间的重复。
5. 脚手架状态按 `(taskId, stepId, helpType)` 隔离；进入新 Step 重置或校准。
6. nudge 感知媒体播放、相机、录音、上传、验收和导航等 busy 状态。
7. 会话必须取得单一真实学段；课程支持范围不能代替学生学段。

### P2：课程迁移和质量门禁

1. 先迁移 `lesson_gewu_001`：Phase 提示、54 个 Step 脚手架、L4 泄题、危险行动、提醒时间、Phase 3/4 能力声明。
2. 再迁移其他四门课程的未知边界标题、入口任务、阶段门控与验收 warning。
3. 审查并合入 Cursor、Kimi 分支；解决冲突后跑全量 lint、单测、构建和关键浏览器旅程。
4. 保留新版 runner 和人工复核能力；日常按问题运行一次 Diagnostic，正式对外／研究级验收时再做至少三次 live eval、完整旅程和人工复核。

## 7. 阶段门禁

### P0 进入 P1 前

- 学生可见的所有输出路径都有统一策略测试。
- 格物当前已知保护答案和危险行动可被 lint 找到。
- 未知课程字段不会继续静默失效。
- 旧课程在兼容模式下行为保持可运行。

### P1 进入 P2 前

- 视频等原子任务无需二次提交。
- 证据汇总任务仍要求显式提交。
- 一个回合只突出一个主要行动。
- Step 切换不继承错误脚手架档位。
- 普通拍照与真实危险安全策略均有测试。

### 正式对外／研究级验收（当前建议项）

- 安全漏报、保护答案泄露、错误推进、丢字截断、未知配置静默失效：0。
- 关键旅程成功率：100%。
- 语境相关率：至少 95%。
- 无关安全提醒和无意义复读：各不高于 2%。
- 关键真实模型场景连续三次不触发硬失败。
- SPEC、运行时和评测中的字段与时间值一致。
