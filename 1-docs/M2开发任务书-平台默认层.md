## 1. 这个阶段要解决什么

**一句话**：让课程作者能用 md 改掉同伴的语气和流程话术，不改 JS、不发版。

现在做不到。`_platform/` 只有 3 份底线规则 + 1 份标签树，本该属于平台包的内容全部硬编码在 JS 里。最直接的后果：

- `人设侧重` 这个字段**两侧都还不存在**（已核实：SPEC 里没有、5 门课的 `course.md` 里没有、JS 零读者）。目标架构 §2.5 把它列为"写了不生效"，实际情况是它从未落地——所以 M2-3 不是"修一个失效字段"，而是**新建这条通路**：SPEC 加字段 → parser 解析 → 合并进 Prompt。
- 学生看到的入场、导航、到达确认、验收反馈、求助这些话，全部写死在 `service.js` 的 `workflowResult()`（14 个 intent 分支，全文件 135 条中文字面量）。教研想调一个字都要改代码。
- 学段字数规范存在**两份互不知情的硬编码**：`prompt.js` 的 `gradeDialoguePolicy()` 给模型的指令写"初中 50–80 字"，`dialogue-policy.js` 的 `gradeLimit()` 事后截断按 100 字。两处数字对不上，谁也不是权威。

这是对「承诺1 换课自由」最大的违背——"换课程只需 md"目前在系统侧不成立。

## 3. 任务分解

按这个顺序做。每一步独立可交付、独立测试，不要攒到最后一起提。

### M2-1 建立默认层编译与合并机制（地基，最先做）

不要先写 6 份 md。先把"读 md → 合并课程覆盖 → 交给消费者"这条链打通，用**一份**最简单的 `defaults.md` 验证它，再批量补其余五份。

产出：

1. `server/course/platform-defaults.js`（新文件）
   - 读取 `_platform/` 下的默认层 md，解析头部声明块：
     ```md
     > overridable: true
     > merge: by-key
     > course-field: 人设侧重
     ```
   - `merge` 三种语义：`by-key` 逐键覆盖 / `replace` 整体替换 / `append` 追加。
   - 文件**缺失时不报错**，回落到 JS 现有常量（双轨期，见 §5）。缺失要 `logger.debug` 一条，不要静默。
   - 内容进 SHA-256 版本，与 `platformRules.version` 一起参与缓存失效。

2. `mergeDefaults(platformDefaults, courseOverrides)` 纯函数
   - 执行 D4 白名单：不可覆盖的键即使课程写了也丢弃，并**返回一条 warning 列表**（不要静默丢，这正是现在 `人设侧重` 的病）。
   - 不可覆盖清单以 `_platform/README.md` §覆盖白名单 为准。

3. 接入 `compiler.js`，产物挂在 `course.platformDefaults` 上。

4. **数值默认要同时供给两条链**（已定：单一权威，两条链不分叉）。
   `parseLesson` 被 `compiler.js:193`（服务端私有）和 `sync-lessons.mjs:128`（浏览器公开包）共用，
   而这五个数值**现在已经进了公开包**（87 个任务各一份，前端 `app-controller.js:530` 真的在读
   `suggestedSeconds` 显示"建议 N 分钟"）。所以只给服务端读会当场分裂：服务端按 md 新值判断提醒，
   浏览器还显示旧的 15 分钟，同一个数字两个答案。
   **硬约束：`parseLesson` 保持同步纯函数**——默认值由调用方读好后当可选入参传进去
   （`parseLesson(source, { defaults })`），不要在它内部读文件。否则它得变 async，两条链都要改，
   波及面立刻放大。

DoD：
- `platform-defaults.test.js`：声明块解析（三种 merge 各一例）、文件缺失回落、白名单拦截并产出 warning、版本随内容变化。
- 用 `defaults.md` 打通端到端：md 里把 `无操作提醒` 改成 5 分钟，`nudge-policy` 的行为随之变化（有测试）。

### M2-2 `language-levels.md`（第二个做，因为它顺手消掉一处重复）

把 `gradeDialoguePolicy()` 与 `gradeLimit()` 合并成一处权威定义：

```md
> overridable: true
> merge: by-key
> course-field: 学段规范

## 初中
- 字数：50–80
- 硬上限：100
- 句式：鼓励先尝试，再按需要给提示
```

DoD：两个调用点都从 `course.platformDefaults.languageLevels` 取值，`prompt.js` 与 `dialogue-policy.js` 不再各自持有数字；改 md 里的字数上限，截断行为随之变化（有测试）。

### M2-3 `companion.md`

按 D4 拆锁定核与可调侧面：

- **锁定**（课程写了也不生效，要进 warning）：`name`、`posterAsset`/`idleAsset`/`talkAsset`、人设底色；
- **可覆盖**：`character`、`tone`、口头禅。

同时**把 `人设侧重` 这条通路建起来**——这是本阶段对课程团队最可感知的一条。注意它是新建而非修复，三处都要动：

1. `6-lessons/COURSE-SUBMISSION-SPEC.md` §基本信息加字段（可选，默认空）；
2. `src/engine/lesson-parser.js` 的 `course.md` 解析加这个键；
3. `prompt.js:133` 的人设句拼接课程侧重。

DoD：某课程 `course.md` 写了 `人设侧重：更冷静克制，少用语气词`，`buildAgentPrompt` 输出里能看到它；同一课程试图改 `name` 时被拦截并出 warning（两条测试）。**注意 `人设侧重` 属于课程私有配置，不要下发到浏览器公开包**——`sync-lessons` 的白名单要相应处理，并在 `course-format-v2.test.js` 的递归键扫描里加断言。

### M2-4 `voice.md`（工作量最大，放在机制稳定之后）

把 `workflowResult()` 的话术抽成带占位符的模板：

```md
> overridable: true
> merge: by-key
> course-field: 话术覆盖

## onboarding.navigation
好，先跟紧小组和老师。我把前往「{location}」的高德地图打开，到了再告诉我。
```

三条硬约束，不要偏离：

1. **只搬文案，不动控制流**。`workflowResult()` 的分支结构、`toolCalls`、`dialogueMove`、状态写入全部保持原样。这一步的正确性标准是"行为完全不变，只是文字来源变了"。
2. **占位符缺值必须可见**。模板要 `{location}` 而课程没给，输出 `{location}` 字面量或抛错都可以，**不要静默变成空串** —— 学生会看到"我把前往「」的地图打开"。
3. **模板过 `findSpoiler`**。话术模板是课程可写的，因此必须和模型输出一样过防剧透，不能因为"是模板"就跳过。

建议分两批：先搬 `onboarding.*` 和 `navigation.*`（约 12 条，覆盖入场全流程），跑通再搬其余。

DoD：`voice.test.js` 逐 key 断言渲染结果；占位符缺值有明确行为（有测试）；`agent.test.js` / `dialogue-contract.test.js` / `anti-loop.test.js` **一条不改**就能全绿——如果需要改这些测试，说明行为变了，停下来先说明原因。

### M2-5 `scaffolding.md` 与 `tool-defaults.md`（可延后）

`scaffolding.md`：定义 L0–L4 各档语义（现在代码里取档，但"L2 是什么"没有任何地方写），以及升降策略参数（第几次求助升档、是否降档）。当前只升不降，降档策略是**新行为**，要先跟我确认再实现。

`tool-defaults.md`：**只搬学生可见的文案**——`src/engine/tool-registry.js:8-17` 的 10 个工具显示名、`:25` 的默认字段 label。`:123` 的中文正则匹配器（`/实物|识别/.test(detail)` 决定扫码器切物体识别模式）**留在代码里**，它是匹配逻辑而非文案，教研不该也不能改它。

- **不要做 Course IR**。那是 M1，不是 M2 的前置。
- **不要新建 `_platform/rules/` 子目录**。README 的清单里写了 `rules/`，但实际三份规则在 `_platform/` 根下，`platform-rules.js:6-8` 也按根路径读。**保持现状，改 README 的表述**（这是文档 bug，不是代码 bug）。

## 8. 已定的四个判断题（2026-08-07 回复 Cursor）

| 问题 | 定案 | 理由 |
|---|---|---|
| `defaults.md` 数值如何同时供给服务端与浏览器包 | **可选入参传进 `parseLesson`，两条链读同一份 md** | 这五个数值已在公开包里且前端在读；只给服务端会让同一数字有两个答案。详见 §3 M2-1 第 4 点，注意保持 `parseLesson` 同步 |
| `tool-defaults.md` 做不做 | **做，只搬 10 个工具显示名与默认 label；中文正则匹配器留代码** | 学生可见、教研会改的进 md；决定程序行为的留代码 |
| 脚手架降档 | **不引入**。本阶段只在 `scaffolding.md` 写清 L0–L4 语义与现有升档参数 | M2 的正确性标准是"行为不变、只换来源"，混入新行为就分不清是搬错还是新功能的毛病；且"何时该收回提示"是教学问题，需教研先定 |
| `voice.md` key 命名 | **与 `decision.intent` 一一对齐**（如 `onboarding_navigation`） | 搬运要可机械核对：14 个分支对 14 个 key，漏一条 grep 就能发现。任务书里 `onboarding.navigation` 只是随手举例，不是方案。可读性等文件写出来再改，那时是纯重命名，很便宜 |
