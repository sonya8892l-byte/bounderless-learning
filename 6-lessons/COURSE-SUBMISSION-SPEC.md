# 课程 Markdown 包提交规范

本文件是课程包的唯一提交标准。Markdown 是结构化课程数据的可读载体；标题层级、字段名、枚举值和引用路径都会被工程解析。课程作者只维护本课内容，平台通用能力由平台层统一提供。

## 1. 四层与它们的归属文件

这是课程包最重要的结构。任何课程流程都由以下四层组成：

| 层级 | 表达什么 | 写在哪里 | 数量与顺序怎么改 |
|---|---|---|---|
| **Phase（课程阶段）** | 全班当前处于哪一段教学情境，例如“现场采证”“推理推演” | `course.md（课程总表）`的`## 阶段编排`；该阶段的 AI 规则写在`prompts/phaseN-*.md` | 新增、删除或调整`### Phase N：名称`；文件名中的 N 与 Phase 编号一致 |
| **Role（学生角色）** | 学生以什么身份完成专属任务 | `roles/<role-id>.md（角色文件）` | 一个角色对应一个文件；角色数量等于角色文件数量；角色显示顺序由`排序`决定 |
| **Task（任务）** | 角色要完成的一项完整成果 | 角色文件中的`### 任务N：名称`；选择角色前的公共任务写在 Phase 下的`#### 阶段任务N：名称` | 按标题顺序新增、删除或调整任务；`id`在所属轨道内保持稳定 |
| **Step（小步）** | 完成任务所需的一次明确行动与验收 | Task 下的`#### Step N：名称`；阶段任务下使用`##### Step N：名称` | 按标题顺序新增、删除或调整小步；每个 Step 独立配置工具、证据与验收 |

Phase 与角色任务使用两条独立游标：

- `phaseId（当前阶段标识）`决定顶栏阶段、阶段开场和 Phase 提示规则。
- `currentTaskIndex（当前任务序号）`与`guidanceStepIndex（当前小步序号）`决定学生正在做哪项角色任务和哪一步。
- 教师推进 Phase 不会替学生跳过角色任务；完成角色任务也不会自动替教师切换 Phase。
- `#### 阶段任务N`用于选择角色前的公共导入活动。学生完成入口阶段任务后，再进入角色领取和角色任务轨道。

### 1.1 想改什么，就改哪里

| 修改目标 | 文件与字段 |
|---|---|
| 课程名称 | `course.md`第一行`# 课程名称` |
| 场地、时长、年级、分组 | `course.md / ## 基本信息` |
| 课程核心问题 | `course.md / ## 核心问题` |
| Phase 数量、名称、时长、模式、地点 | `course.md / ## 阶段编排 / ### Phase N` |
| Phase 首次进入时显示的话 | `prompts/phaseN-*.md / ## 开场白模板` |
| Phase 中絮絮的目标、行为、边界与转场话术 | 同一 Phase Prompt 的其余四个二级标题 |
| 角色数量 | 新增或删除`roles/*.md` |
| 角色名称 | 对应角色文件第一行`# 角色名称` |
| 角色顺序 | 对应角色文件`## 基本信息 / 排序` |
| 角色地点与围栏 | 对应角色文件`## 基本信息 / 地点、地理围栏` |
| 角色选择文案、图片、收集物 | 对应角色文件`## 基本信息` |
| 角色任务数量、名称和顺序 | 对应角色文件中的`### 任务N：名称` |
| 任务的小步数量、名称和顺序 | 对应 Task 下的`#### Step N：名称` |
| 学生本步要做什么 | Step 的`小步目标`、`学生行动` |
| 使用哪种活动工具 | Task 或 Step 的`功能模块`、`工具参数` |
| 本步需要什么证据 | Step 的`证据要求`、`完成方式`、`##### 验收标准` |
| 学生卡住时如何提示 | Task 或 Step 的`##### 脚手架` |
| AI 当前可引用哪些知识 | `knowledge/*.md`与 Step 的`知识引用` |
| AI 当前不能透露什么 | `course.md / ## 课程限制规则`与 Step 的`限制引用` |
| 全课量规兜底 | `evaluation.md` |
| 时间银行 | `time-bank.md` |
| 课程图片、视频与地图 | `assets/`，再由对应任务或`course.md`字段引用 |

## 2. 平台默认与课程包的边界

平台通用人设、通用话术、语言分级、脚手架等级语义、活动工具底层行为、安全、隐私和全局默认值统一放在`_platform/（平台默认层）`。需要改变所有课程的共同表现时，去平台层修改。

课程包只写本课独有的数据：课程信息、Phase、角色、任务、Step、知识、限制、验收、时间银行和素材。不要把平台通用规则复制进课程文件，也不要在课程 Markdown 中描述前端、数据库、鉴权或部署实现。

## 3. 标准目录

```text
lesson_<course_id>/
├── course.md
├── roles/
│   └── <role-id>.md
├── prompts/
│   └── phaseN-<slug>.md
├── knowledge/
│   └── <topic>.md
├── evaluation.md
├── time-bank.md
└── assets/
    ├── backgrounds/
    ├── maps/
    ├── roles/
    ├── tasks/
    ├── tokens/
    └── videos/
```

`evaluation.md`和`time-bank.md`按课程需要提交。其余运行文件必须与本课实际流程对应；不要创建只供阅读、没有解析消费者的课程说明章节。

## 4. `course.md`：课程总表

`course.md`集中保存课程级字段、课程目标、阶段编排和课程限制。三个命名空间都直接写在这个文件中：

- `## 课程目标体系`
- `## 阶段编排`
- `## 课程限制规则`

### 4.1 基本信息

```markdown
# 故宫600年不积水的秘密

## 基本信息
- 系列：格物
- 系列代码：gewu
- 主题模板：gewu
- 场地：故宫博物院（中轴线区域）
- 坐标中心：116.397, 39.918
- 时长：6小时（含午休）
- 适用年级：小学高年级 / 初中 / 高中
- 分组：6人一组，每人一个角色
- 课程层级：深度探究版
- 层级代码：inquiry
```

字段作用：

| 字段 | 作用 | 要求 |
|---|---|---|
| H1 标题 | 课程列表、学生入口和 AI 课程身份 | 必填 |
| `系列` | 学生入口品牌与教师课程列表 | 建议填写 |
| `系列代码` | 课程系列的稳定机器标识 | 必填；同一系列保持一致 |
| `主题模板` | 选择课程主题样式 | 必填；使用平台已注册的主题值 |
| `场地` | 学生入口、组织问答和地点回退 | 必填 |
| `坐标中心` | 教师场次地图与安全中心 | 正式场地课程必填，格式为经度、纬度 |
| `时长` | 课程信息与时间问答 | 必填 |
| `适用年级` | 课程信息与组织问答 | 必填 |
| `分组` | 课程信息与组织问答 | 必填 |
| `课程层级` | 学生入口的课程深度标签 | 分层课程填写 |
| `层级代码` | 课程层级的稳定机器标识 | 分层课程与课程层级同时填写 |

### 4.2 核心问题

```markdown
## 核心问题
故宫建成600年，历经无数暴雨，为何几乎从不积水？
```

正文第一行作为学生端显示的全课核心问题。

### 4.3 学生端角色体系

```markdown
## 学生端角色体系
- collectionName：治水官
- itemName：身份
- 选择眉题：{roleCount}种身份 · {roleCount}段证据
- 选择标题：选择你的{collectionName}身份
- 选择说明：每位成员领取一个本组尚未占用的角色。
- collectionItemName：密符
- collectionPanelName：小组密符
- unlockTarget：璇玑时刻
- 任务阶段：phase-2
```

`collectionName`、`itemName`、`collectionItemName`、`collectionPanelName`、`unlockTarget`和`任务阶段`必填。角色选择文案可使用：

- `{roleCount}`：本课角色数量
- `{collectionName}`：角色集合名
- `{itemName}`：角色单位名
- `{collectionItemName}`：收集物名称
- `{unlockTarget}`：集合后的教学目标名

`任务阶段`表示角色领取后会话所在的初始 Phase。角色数量由`roles/*.md`文件数量决定。

### 4.4 学习视图

只有本课需要指定学生呈现方式时才写：

```markdown
## 学习视图
- enabled：true
- default：dialogue
- allowStudentSwitch：true
```

- `enabled`：是否启用双视图能力。
- `default`：`dialogue`或`challenge`。
- `allowStudentSwitch`：是否允许学生自行切换。

未写时使用平台默认；全局表现要在平台层调整。

### 4.5 学生端视觉素材

```markdown
## 学生端视觉素材
- 课程封面：assets/backgrounds/cover.png
- 导航地图：assets/maps/navigation-map.png
- 导入占位图：assets/videos/video-storm-coming.png
```

- `课程封面`用于课程入口。
- `导航地图`用于学生小组页和教师场次地图。
- `导入占位图`用于导入媒体没有视频源时的预览。

### 4.6 课程目标体系

目标按`DK（学科知识）`、`DS（学科能力）`、`DC（课程级核心能力）`记录。每条都使用“编号 + 名称 + 冒号 + 描述”：

```markdown
## 课程目标体系

### 学科知识 DK
- DK-01 排水系统构成：认识课程要研究的关键系统构成。

### 学科能力 DS
- DS-01 现场观察：从现场对象中提取可复核信息。

### 课程级核心能力 DC
- DC-01 证据意识：用证据支撑结论并说明边界。
```

Task 和 Step 的`能力标签`引用这里的编号。标签使用逗号分隔，例如`DK-01, DS-01, DC-01`。

### 4.7 阶段编排

每个 Phase 使用同一组课程级字段：

```markdown
## 阶段编排

### Phase 1：沉浸叙事
- 时长：20min
- 模式：集体（全班）
- 地点：集合区域
```

- Phase 标题中的编号生成`phase-N`。
- `时长`用于阶段倒计时与时间上下文。
- `模式`和`地点`进入阶段组织信息。
- 教师端负责实际 Phase 推进；AI 的转场话术写在对应 Phase Prompt。

#### 选择角色前的阶段任务

阶段任务与角色任务使用同一套 Task/Step 字段，额外增加`执行单位`：

```markdown
#### 阶段任务1：查看情境图
- id：phase-1-task-1
- 执行单位：个人
- 功能模块：A06(沉浸媒体)
- 工具参数：{"media":{"type":"video","poster":"videos/opening.png","posterOnly":true,"requireCompletion":true}}
- 完成方式：tool_result
- 建议时长：3min
- 收口方式：auto_on_last_step
- 推进方式：auto_after_validation
- 通过条件：学生确认已查看情境图
- 证据要求：媒体工具返回查看确认
- AI引导方向：确认学生看完，不提前解释后续结论

###### 验收标准
媒体工具返回查看确认即通过。

##### Step 1：查看情境图
- id：phase-1-task-1-step-1
- 小步目标：查看开场情境
- 学生行动：观察并确认已查看
- 位置：none
- 完成方式：tool_result
- 证据要求：媒体工具返回查看确认
- 功能模块：A06(沉浸媒体)
- 工具参数：{"media":{"type":"video","poster":"videos/opening.png","posterOnly":true,"requireCompletion":true}}
- 最大尝试：3
- 失败处理：请先查看情境图，再点击确认
- 教师介入：媒体持续无法打开
- 通过后：role-stage:complete

###### 验收标准
媒体工具返回查看确认。
```

`执行单位`填写`个人`、`小组`或`全班`。当前学生会话按个人保存完成记录，因此需要每名学生各自完成的入口任务统一写`个人`。

### 4.8 课程限制规则

限制章节必须是可精确引用的命名分区：

```markdown
## 课程限制规则

### 核心数据限制

| 限制项 | 不可透露的内容 | 保护原因 | 解除条件 |
|---|---|---|---|
| 精确数量 | 某个任务答案 | 学生需要自行观察 | 对应任务完成后 |

### 跨角色隔离

- 未解锁前，不能向当前角色透露其他角色的结论。
```

Step 使用完整路径引用：

```markdown
- 限制引用：course.md#课程限制规则/核心数据限制
```

标题必须完全匹配。表格中的保护内容会进入输出保护和解锁判断；命名章节只把当前 Step 需要的最小片段送入 AI。

## 5. `roles/*.md`：角色、任务和 Step

一个角色一个文件，文件名使用稳定英文 slug，例如`dragon-counter.md`。文件名生成`roleId（角色标识）`，不要用角色中文名驱动工程逻辑。

### 5.1 角色基本信息

```markdown
# 数龙官

## 基本信息
- 排序：1
- 地点：三大殿三台
- 地理围栏：中心(116.3972, 39.9171) 半径100m
- 选择说明：追踪对象的形态与数量，建立现场证据。
- 角色卡图：assets/roles/role-card-dragon-counter.png
- 角色徽章图：assets/roles/badge-dragon-counter.png
- 收集物：Y
- 收集物图：assets/tokens/token-Y.png
```

- `排序`决定角色选择页顺序。
- `地点`和`地理围栏`为该角色任务提供位置继承。
- `选择说明`、`角色卡图`、`角色徽章图`直接进入角色选择界面。
- `收集物`和`收集物图`用于角色全部任务完成后的奖励卡与小组收集页。

### 5.2 Task 字段

```markdown
## 任务列表

### 任务1：观其形
- id：task-1
- 位置模式：inherit_role
- 到达验证：manual
- 最短停留：0min
- 建议时长：15min
- 无操作提醒：8min
- 提醒冷却：8min
- 最大主动提醒：1
- 推进方式：auto_after_validation
- 收口方式：auto_on_last_step
- 任务图：assets/tasks/task-1.jpg
- 配置：采集能够回答任务问题的现场证据
- 通过条件：全部必做 Step 通过
- 目标关联：DK-01, DS-01, DC-01
- 能力标签：DK-01, DS-01, DC-01
```

| 字段 | 作用 |
|---|---|
| `id` | 进度、任务图、事件和工具实例的稳定标识 |
| `位置模式` | `inherit_role`继承角色地点；也可使用`none`、`point`、`geofence`、`route`、`area` |
| `地点`、`坐标`、`围栏半径` | 任务需要覆盖角色地点时填写 |
| `到达验证`、`最短停留` | 位置验证方式与停留门槛 |
| `建议时长` | 任务时长提示 |
| `无操作提醒`、`提醒冷却`、`最大主动提醒` | 主动提醒节奏 |
| `推进方式` | 任务完成后的推进控制 |
| `收口方式` | 最后一个 Step 通过后的任务终审控制 |
| `任务图` | 任务卡图片 |
| `配置` | 学生任务卡上的简要要求 |
| `通过条件` | 任务级验收上下文 |
| `完成方式`、`证据要求` | 没有可执行 Step 时的任务级验收；有显式 Step 时由当前 Step 优先 |
| `目标关联` | 任务检索知识时的语义线索 |
| `能力标签` | 任务对应的课程目标编号 |
| `前置` | 角色任务图中的前置任务 id 列表 |

#### 推进方式

| 值 | 行为 |
|---|---|
| `auto_after_validation` | 任务验收通过后自动进入下一任务 |
| `ai_suggest` | AI 提示学生确认后推进 |
| `teacher` | 等教师端推进 |

#### 收口方式

| 值 | 行为 |
|---|---|
| `auto_on_last_step` | 最后一个必做 Step 通过后完成任务 |
| `task_ai_evaluation` | Step 全部通过后，再进行任务级 AI 终审 |
| `task_teacher_confirm` | Step 全部通过后，等待教师终审 |

### 5.3 Task 就地引导与脚手架

```markdown
##### 引导
说明本任务的引导目标、提问顺序和不能提前说出的结论。

##### 脚手架
| L0 | 肯定学生当前有效动作，不增加答案线索。 |
| L1 | 给一个观察方向。 |
| L2 | 给一个可执行方法。 |
| L3 | 给结构化核验框架。 |
| L4 | 给完整核验步骤，仍由学生填写结论。 |
```

Task 级内容作为本任务的默认值。Step 写了同名段落时，Step 优先。脚手架等级的通用语义由平台层统一定义；课程只写本任务的具体提示。

### 5.4 Step 字段

```markdown
#### Step 1：拍摄现场全景
- id：task-1-step-1
- 小步目标：获得能够确认对象与环境位置关系的证据
- 学生行动：拍摄一张同时包含对象和环境参照的全景
- 位置：inherit
- 完成方式：ai_evaluation
- 证据要求：至少1张清楚照片；主体与环境参照同时入镜
- 功能模块：A01(拍照)
- 工具参数：{"photo":{"prompt":"请拍摄主体与环境参照。","minCount":1,"maxCount":2,"accept":"image/*"}}
- 知识引用：K-01
- 限制引用：course.md#课程限制规则/核心数据限制
- 常见误区：只拍局部，无法判断位置关系
- 最大尝试：3
- 失败处理：指出缺少主体、环境参照或清晰度中的首要一项
- 教师介入：连续3次仍无法取得可辨认证据
- 通过后：step:task-1-step-2

##### 脚手架
| L1 | 检查画面中是否同时有主体和环境参照。 |
| L4 | 按“主体完整、环境可定位、比例可比较”逐项核验。 |

##### 验收标准
至少1张清楚照片；主体与环境参照同时入镜。
```

| 字段 | 作用 |
|---|---|
| `id` | Step 进度、证据和工具状态的稳定标识 |
| `小步目标` | AI 当前目标与任务卡说明 |
| `学生行动` | 学生本步的明确动作 |
| `位置` | `inherit`继承任务地点；`none`表示无位置要求 |
| `地点`、`坐标`、`围栏半径`、`最短停留`、`到达验证` | 本步需要独立位置门槛时填写 |
| `完成方式` | 选择本步验收路径 |
| `证据要求` | 任务卡与验收上下文 |
| `功能模块`、`工具参数` | 实例化本步活动工具 |
| `知识引用` | 定向检索当前需要的知识条目 |
| `限制引用` | 注入当前需要的课程限制片段 |
| `常见误区` | 当前小步 AI 对话上下文 |
| `最大尝试` | AI 验收尝试上限 |
| `失败处理` | 规定失败反馈应该指出什么 |
| `教师介入` | 规定需要教师处理的情况，并参与发布校验 |
| `通过后` | 标记下一个 Step 或任务图目标 |

#### 完成方式

| 值 | 使用场景 |
|---|---|
| `user_confirm` | 学生确认已完成，无工具证据 |
| `tool_result` | 由活动工具结果判定 |
| `ai_evaluation` | AI 按本步证据与验收标准判定 |
| `teacher_confirm` | 必须由教师审核 |
| `location_event` | 由位置到达事件判定 |
| `compound` | 组合多类证据判定 |

`ai_evaluation`必须提供清楚的`证据要求`和`##### 验收标准`。`teacher_confirm`必须写明`教师介入`。

#### 通过后

- `step:<stepId>`：声明下一个 Step，书写顺序仍是小步执行顺序。
- `role-stage:<taskId>`：当前任务完成后进入指定角色任务。
- `role-stage:complete`：当前角色轨道结束。

角色任务的固定拓扑同时受`前置`和`role-stage:<taskId>`约束。

## 6. 活动工具

`功能模块`选择活动能力，`工具参数`提供本课参数。常用模块：

| 模块 | 典型用途 | 常用工具键 |
|---|---|---|
| `A01` | 拍照、录音、文字表单、画板标注 | `photo`、`audio`、`text`、`sketch` |
| `A02` | 单题或多题评测 | `quiz` |
| `A03` | 拼合、排序、流程和证据墙 | `builder` |
| `A04` | 沙盘与参数推演 | `simulation` |
| `A05` | 同伴核验、投票、分工与讨论记录 | `team` |
| `A06` | 图片、音频、视频等沉浸媒体 | `media` |
| `A07` | 扫码与实物识别 | `scanner` |

工具参数必须是单行合法 JSON，键名与模块匹配：

```markdown
- 功能模块：A01(拍照)
- 工具参数：{"photo":{"prompt":"拍摄一张全景。","minCount":1,"maxCount":3,"accept":"image/*"}}
```

位置导航、阶段倒计时、师生通信和主 AI 对话由平台提供，不写进`功能模块`。

## 7. `prompts/phaseN-*.md`：Phase 提示规则

每个 Phase Prompt 必须且只能包含以下五个二级标题，顺序固定：

````markdown
# 现场采证阶段提示词

## 阶段目标
学生在本阶段要形成什么认识或成果。

## 絮絮行为
- 应如何提问、反馈和组织对话。

## 开场白模板
```text
进入本阶段时向学生显示的完整开场白。
```

## 禁止行为
- 本阶段不能做什么、不能提前说什么。

## 转场条件
- 达到什么状态时可以提示学生等待教师推进。
````

运行效果：

- `阶段目标`、`絮絮行为`、`禁止行为`和`转场条件`进入该 Phase 的 AI 上下文。
- `开场白模板`在学生首次进入该 Phase 时显示一次，不调用主模型；代码围栏会被去掉。
- `{角色名}`、`{首个地点}`和`{学生名字}`会按当前会话替换。
- `转场条件`约束 AI 的转场话术；教师端仍是 Phase 推进的权威入口。
- 不要增加角色差异、关键提示词、流程说明或其他二级标题。角色差异写进对应角色任务，具体提示写进 Task/Step。

## 8. `knowledge/*.md`：课程知识

每个知识文件可包含多个知识条目：

```markdown
## K-01 条目标题
- 主题：排水构造
- 内容：供 AI 检索的事实、方法与边界。
- 标签：排水, 结构, 现场观察
- 来源：来源名称或链接说明
- 适用角色：dragon-counter, slope-surveyor
- 揭示时机：phase-2
```

- H2 标题中的`K-01`是`知识引用`使用的稳定 id。
- `适用角色`限制检索角色；留空表示全角色。
- `揭示时机`限制最早可用阶段或任务。
- `来源`会随 AI 回答生成引用信息。
- 课程答案、可检索事实和解释边界写在知识条目中，不重复写进角色基本信息。

## 9. `evaluation.md`：全课验收兜底

Task 或 Step 已写`##### 验收标准`时，就地标准优先。`evaluation.md`只承担没有就地标准时的全课量规兜底：

```markdown
# 课程评估规范

## 评估原则
- 证据优先于结论完整度。
- 允许带边界的暂定结论。

## 通用量规
| 维度 | 达标表现 | 需要修订 |
|---|---|---|
| 证据 | 来源清楚且与主张对应 | 只有结论或来源不明 |
```

课程如果要求每一步都精确验收，应给每个 Step 写`##### 验收标准`。

## 10. `time-bank.md`：时间银行

时间银行独立于角色任务进度。它只更新可赚取、分配和赠送的时间余额，不推进 Task 或 Step。

```markdown
# 时间银行

## 基本设置
- enabled：true
- initialBalance：0
- maxBalance：30

## 赚取规则
- correct_answer：2
- photo_checkin：3
- location_checkin：2

## 分配规则
- allowGift：true
- maxGiftPerAction：5

## 任务池

### 快问快答类
- id：tb-quiz-01
- 类型：quiz
- 题目：题目正文
- 答案：A
- 奖励：2
```

答案、验证参数和定位坐标属于服务端私有字段，不会下发学生浏览器。

## 11. 素材引用

- Markdown 中统一写`assets/`开头的课程内路径。
- 角色卡、徽章、收集物图在角色基本信息中引用。
- 任务卡图在 Task 的`任务图`中引用。
- 工具图片、海报和参考图在`工具参数`中引用。
- 文件名使用稳定英文 slug，避免空格和临时编号。
